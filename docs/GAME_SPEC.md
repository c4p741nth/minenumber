ถ้าโค้ดขัดกับเอกสารนี้ = โค้ดผิด ถ้าเอกสารนี้ขัดกับ `concept.md` = เอกสารนี้ชนะ (เพราะ concept.md เป็น brainstorm ที่ยังไม่ตัดสินใจ)

## 1. ภาพรวม

เกมกระดานเลือกตัวเลขสำหรับเล่นในที่ประชุม/งานอีเวนต์
**MC (พิธีกร) เป็นคนกดหน้าจอคนเดียว** — ผู้เล่นไม่ต้อง join session, ไม่มี network, ไม่มี backend
ทีมช่วยกันคิดแล้วบอกเลข MC กดให้

**เป้าหมาย:** เป็นทีมสุดท้ายที่รอด ทีมที่ถูกคัดออกจะได้อันดับย้อนกลับ (ออกก่อน = อันดับท้าย)

## 3. ประเภทของช่อง

ทุกเลขในช่วง a–b มีสถานะหนึ่งใน:

| สถานะ | ความหมาย | แสดงผล |
|---|---|---|
| `hidden` | ยังไม่เปิด | ปุ่มแสดงตัวเลข กดได้ |
| `safe` | เปิดแล้ว ไม่มีระเบิด | ปุ่มจาง ✓ กดไม่ได้ |
| `detonated` | ระเบิดจริงระเบิดที่นี่ | ปุ่มสีแดง 💥 กดไม่ได้ |
| `defused` | เคยมีระเบิดแต่กู้สำเร็จ ระเบิดย้ายไปแล้ว | ปุ่มสีเขียว 🔧 กดไม่ได้ (= safe) |
| `glitched` | glitch bomb ระเบิดที่นี่ | ปุ่มสีม่วง ⚡ กดไม่ได้ |

ช่องที่เปิดแล้วทุกชนิด **กดซ้ำไม่ได้ตลอดเกม**

## 4. ประเภทระเบิด

### 4.1 Real bomb (ระเบิดจริง)
- เปิดเจอ → เข้าโหมด **ตัดสาย** (ข้อ 5)
- กู้สำเร็จ → ช่องนั้นเป็น `defused` (ปลอดภัยถาวร) ระเบิดลูกนั้น **ย้ายไปช่อง `hidden` อื่นแบบสุ่ม** จบ turn ทันที
- กู้สำเร็จแต่**ไม่มีช่อง `hidden` ให้ย้าย** (ทุกช่องที่เหลือเป็นระเบิดหมด) → ระเบิดลูกนั้น**ถูกทำลาย หายจากเกม** ไม่ค้างเป็นระเบิดผี
- กู้ไม่สำเร็จ → ช่องเป็น `detonated`, **ทีมถูกคัดออก**, ระเบิดลูกนั้น**หายไปจากเกม** (ไม่ย้าย)

### 4.2 Glitch bomb (ระเบิดกลิตช์)
- เปิดเจอ → **ไม่มีโหมดตัดสาย ไม่ตาย**
- ทีมนั้นติดสถานะ `glitched` เป็นเวลา **2 turn ของทีมตัวเอง** → ใช้การ์ดไม่ได้ และ**จั่วการ์ดไม่ได้**
- ช่องเป็น `glitched`, ระเบิดกลิตช์ลูกนั้นหายไปจากเกม (ไม่ย้าย)
- จบ turn ทันที
- Glitch bomb **ไม่นับ**ในสูตร `ระเบิด = ทีม − 1` — เป็นระเบิดส่วนเกินที่เพิ่มเข้ามาตาม % ที่ตั้งไว้

**เหตุผลของ design นี้:** ถ้า glitch นับรวมในโควตา จำนวนระเบิดที่ฆ่าได้จะน้อยกว่าทีม−1 ทำให้เกมจบไม่ลง (อาจเหลือ 3 ทีมโดยไม่มีระเบิดเหลือ)

## 5. โหมดตัดสาย (Defuse)

เข้าเมื่อเปิดเจอ real bomb เท่านั้น

1. UI ขึ้น modal เต็มจอ แสดงสายแดง 🔴 และสายน้ำเงิน 🔵
2. **ผลถูกสุ่มไว้ล่วงหน้าตั้งแต่ก่อนแสดง modal** (`survived = rng() < 0.5`) — ไม่ผูกกับสีที่เลือก ทั้งสองสายมีโอกาส 50/50 เท่ากันเสมอ
3. ทีมเลือกสาย → animation หน่วง 2–3 วินาที (สร้าง suspense) → เฉลยผล
4. เล่นเสียง + effect ตามผล

**สำคัญ:** ห้าม implement เป็น "สายที่ถูกคือสีนี้" แล้วเทียบ เพราะถ้าสุ่มสีถูกไว้ล่วงหน้าและมี state leak ผู้เล่นเดาได้ ให้สุ่ม**ผลลัพธ์**ตรง ๆ

## 6. ลำดับ turn

- ทีมเรียงตามลำดับที่ตั้งไว้ วนไปเรื่อย ๆ ข้ามทีมที่ถูกคัดออก
- `direction: 1 | -1` — การ์ด Reverse สลับค่านี้
- **ตาหนึ่งของทีม = ต้องเปิดป้ายให้ครบ `pendingOpens` ใบ** (ปกติ 1, เพิ่มด้วยการ์ด Attack)
- ถ้าทีมโดนคัดออกกลางคัน `pendingOpens` ที่เหลือถูกยกเลิก

### ลำดับขั้นใน 1 turn
```
เริ่ม turn
 ├─ ลด glitch counter ของทีมนี้ลง 1 (ถ้ามี)
 ├─ [ช่วงใช้การ์ด] ทีมใช้การ์ดได้กี่ใบก็ได้ (ถ้าไม่ติด glitch/block)
 ├─ [ช่วงเปิดป้าย] เปิดจนครบ pendingOpens
 │    └─ แต่ละครั้ง: ตรวจชนิดช่อง → resolve → ถ้าตายให้ตัด turn ทิ้ง
 ├─ จั่วการ์ด (ถ้ารอดจบ turn และไม่ติด glitch) — ดูข้อ 7.1
 └─ ส่งต่อทีมถัดไปตาม direction
```

### ตัวจับเวลา
- นับถอยหลังตั้งแต่**ช่วงใช้การ์ด** (`cards`) ต่อเนื่องถึง**ช่วงเปิดป้าย** (`opening`)
- หมดเวลา → **สุ่มเปิดช่อง `hidden` ให้อัตโนมัติ 1 ช่อง** พร้อมเสียงเตือน (ลงโทษการอืด แต่ยังลุ้นได้)
  - ใช้ได้ทั้งช่วงคิดและช่วงเปิดป้าย — กันเกมค้างถ้าทีมอืดตอนคิดการ์ด
- ตั้งเป็น 0 = ปิดการจับเวลา

## 7. ระบบการ์ด

### 7.1 การได้การ์ด
- **จั่วอัตโนมัติ 1 ใบ เมื่อจบ turn โดยรอด** (ไม่โดนอะไรเลย)
- ถ้าเปิดเจอ glitch bomb → **ไม่ได้จั่ว**
- **มือถือได้ไม่จำกัด** (ค่า default; ตั้ง "จำกัดมือสูงสุด" ได้ 3–7 ใบ — เกินแล้วจั่วไม่เข้า)
- เริ่มเกมทุกทีมได้ **3 ใบสุ่ม** (ตั้ง 0–5 ได้)
- **ไพ่ในมือคว่ำหน้าทั้งหมด** — กดเปิดดูทีละใบ (เปิดแล้วปิดกลับไม่ได้) แล้วเลือก **ใช้ หรือ ทิ้ง**
- ทิ้งการ์ดไม่จบตา ไม่ได้จั่วชดเชย (แค่ลดมือ)
- **ไม่มีระบบ ability point** — ตัดทิ้งเพื่อลดความซับซ้อน การ์ดคือทรัพยากรเดียว

### 7.2 รายการการ์ด

| การ์ด | ผล | น้ำหนักสุ่ม | ใช้ตอนไหน |
|---|---|---|---|
| **Scan** 🔍 | เลือกเลขเป้าหมาย → ระบบตรวจ**ช่วงเลขซ้าย–ขวา**รอบเป้าหมาย (±R เช่น เลือก 20 รัศมี 3 = ตรวจ 17–23) แล้วตอบว่ามีระเบิดหรือไม่ (ตอบแค่ มี/ไม่มี ไม่บอกจำนวนหรือตำแหน่ง) | 25 | ก่อนเปิดป้าย |
| **Skip** ⏭ | จบ turn ทันทีโดยไม่ต้องเปิดป้าย ส่งต่อทีมถัดไป | 20 | ก่อนเปิดป้าย |
| **Block** 🛡 | เลือกทีมเป้าหมาย → ทีมนั้นใช้การ์ดไม่ได้ใน turn ถัดไปของตัวเอง | 15 | ทุกเมื่อในตาตัวเอง |
| **Reverse** 🔄 | สลับทิศทางการเล่น + จบ turn ทันที (= Skip ในตัว) | 15 | ก่อนเปิดป้าย |
| **Shuffle** 🎲 | สุ่มตำแหน่งระเบิดทุกลูกใหม่ในช่อง `hidden` ทั้งหมด | 10 | ก่อนเปิดป้าย |
| **Attack** ⚔ | เลือกทีมเป้าหมาย → เพิ่ม `pendingOpens` ของทีมนั้น +1 | 15 | ก่อนเปิดป้าย |

น้ำหนักรวม 100 — สุ่มจากถุงไม่จำกัด (ไม่ใช่ deck จำกัดใบ)

**ข้อสรุปการออกแบบ Block (V5):** Block คือการแบนการ์ดของเป้าหมายใน **turn ถัดไป** เท่านั้น
ไม่ใช่การขัดจังหวะแบบ real-time (เช่น block ตอนอีกทีมกำลังใช้การ์ดอยู่)
เพราะเกมนี้เป็น hotseat 1 จอ ไม่มี concurrency — ถ้าทำ real-time จะไม่มีทางรู้ว่า
อีกทีมกำลังจะเล่นการ์ดอะไร พฤติกรรมที่ยืนยันแล้ว: ใช้การ์ดได้เฉพาะตาตัวเอง กี่ใบก็ได้
แต่เมื่อ "เปิดป้าย" แล้วจะกลับมาใช้การ์ดในตานั้นไม่ได้อีก

### 7.3 กติกาการ stack (สำคัญ — เขียนให้ชัด)

**Attack stack:**
- Attack ซ้อนกันได้ไม่จำกัด แต่ละใบ +1 `pendingOpens` ให้เป้าหมาย
- ทีมที่โดน attack **ตอบโต้ได้** โดยใช้ Attack ของตัวเองใส่ทีมอื่น → **โอนภาระทั้งกอง**
  - ตัวอย่าง: A ใส่ B 2 ใบ (B ต้องเปิด 3) → B ใช้ Attack ใส่ C → C ต้องเปิด 3+1 = 4, B กลับไปเปิด 1
  - นี่คือกลไก "ส่งต่อ" แบบแมวระเบิด สร้างความปั่นป่วนตามข้อ 14 ของ concept.md
- ถ้าทีมไหนไม่มี Attack จะโดนเต็ม ๆ

**Block stack:**
- Block ซ้อนกันได้ — B block A แล้ว C block B ได้
- Block ที่โดน block **ยังทำงาน** (Block ไม่ยกเลิกกันเอง) เพราะ Block มีผลใน turn ถัดไป ไม่ใช่ทันที
- ทีมเดียวติด block ได้หลายชั้น = โดนแบนหลาย turn (นับสะสม)

**Shuffle:** ไม่ stack ใช้กี่ใบผลก็เหมือนกัน (แต่เสียการ์ดจริง)

## 8. เงื่อนไขจบเกม

เกมจบเมื่อ **เหลือทีมรอด 1 ทีม**

**อันดับ:** ทีมที่รอดสุดท้าย = อันดับ 1, ทีมที่ตายเป็นทีมสุดท้าย = อันดับ 2, ไล่ย้อนขึ้นไป

### Edge case ที่ต้องจัดการ
| กรณี | วิธีจัดการ |
|---|---|
| ระเบิดหมดแต่ยังเหลือ >1 ทีม (เกิดจาก glitch/defuse) | **เติมระเบิดใหม่** ให้ครบ `ทีมที่เหลือ − 1` ในช่อง hidden พร้อมแจ้ง MC ว่า "เติมระเบิดรอบใหม่" |
| ช่อง hidden เหลือน้อยกว่าจำนวนระเบิด | ลดจำนวนระเบิดลงให้พอดีกับช่อง แล้วแจ้งเตือน |
| ช่อง hidden หมดแต่ยังเหลือ >1 ทีม | ประกาศ**เสมอ**ทุกทีมที่รอด อันดับเท่ากัน |
| ทีมที่ต้องเปิด 3 ใบ ตายตั้งแต่ใบแรก | ยกเลิกที่เหลือ ไปทีมถัดไป |

## 9. Shrinking Mode (วงหด) (Range Shrinking) — OPTIONAL, ปิดไว้ default

**ทำไมถึงปิด default:** เมื่อ range หด density ระเบิดจะพุ่งขึ้นเรื่อย ๆ (5% → 33% ภายใน 9 รอบ) ทำให้ทีมที่เล่นทีหลังเสี่ยงกว่าทีมแรก 6-7 เท่าโดยไม่ได้ทำอะไรผิด และเกมจบเร็วจนจั่วการ์ดไม่ทันใช้

**ถ้าเปิด ต้องทำตามกฎนี้เท่านั้น:**
1. หลังทีมเปิดเจอช่อง safe → หด range จากฝั่งที่ใกล้เลขที่เลือกกว่า
2. **ระเบิดที่ยังอยู่ใน range ใหม่ ห้ามย้าย** — ย้ายเฉพาะลูกที่หลุดออกนอก range (ห้าม re-randomize ทั้งหมด มิฉะนั้นข้อมูลที่ผู้เล่นสะสมและการ์ด Scan จะไร้ความหมาย)
3. **หยุดหดทันที**เมื่อ `จำนวนระเบิด / ช่อง hidden > 0.30` — กันสถานการณ์กดยังไงก็ตาย
4. ต้องเหลือช่อง hidden อย่างน้อย `ทีมที่รอด × 2` เสมอ

**ทางเลือกที่ดีกว่าถ้าอยากให้เกมสั้น:** ลดช่วงเริ่มต้นเป็น 1–30 หรือ 1–40 แทน — สั้นเหมือนกันแต่ density คงที่และแฟร์ตลอดเกม

### 10.1 เพลง background (YouTube)
- ใส่ URL YouTube ในหน้าตั้งค่า → เล่นเพลงพื้นหลังวนลูประหว่างเกม (ใช้ YouTube IFrame Player API ฝัง player ซ่อน — **ห้าม download/แปลงไฟล์**)
- รองรับ `watch?v=` / `youtu.be/` / `playlist?list=` / `shorts` / ID 11 ตัว
- มี ▶/⏸ + slider volume (0–100%) ระหว่างเกม — volume จำใน localStorage
- ว่าง = ไม่เปิดเพลง → ไม่มี iframe ไม่มี network request ไป YouTube
- ออกจากเกม → ทำลาย player หยุดเพลง (ไม่งั้นเพลงเล่นต่อในหน้าเมนู)
- ถ้า iframe API โหลดไม่ได้ (offline/adblock) → ซ่อน UI เพลง เกมไม่พัง
- **หมายเหตุ CSP:** ตอนนี้ `vercel.json` ยังไม่มี CSP header — ถ้าจะเพิ่ม CSP ในอนาคตต้องเปิดให้ `youtube.com` และ `ytimg.com`

## 11. Anti-cheat / การเก็บข้อมูล

ดูรายละเอียด implementation ใน `TASKS.md` Task 2

**หลักการ:**
- ตำแหน่งระเบิด **ห้ามอยู่ใน localStorage แบบอ่านได้** และห้ามอยู่ใน DOM/React DevTools แบบตรง ๆ
- ยอมรับว่านี่คือ **obfuscation ไม่ใช่ security** — key อยู่ใน client bundle ผู้ที่ตั้งใจโกงจริงยังถอดได้ เป้าหมายคือทำให้ "แพงพอที่จะไม่คุ้มโกงกลางวง" ซึ่งพอสำหรับ use case นี้
- ห้าม `console.log` state ของระเบิดใน production build
